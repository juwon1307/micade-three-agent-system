# Micade Website Implementation Gate v1.0

Status: Proposed decisions for approval
Purpose: Resolve the decisions required before production website implementation.

## Decision Register

| Decision | Recommended default | Status |
| --- | --- | --- |
| Primary CTA | Start a conversation, routed to the Contact page | Proposed |
| Launch pages | Home, About, Services, three package pages, Contact | Proposed |
| Resources and Blog | Launch Resources first; add Blog after the initial service pages | Proposed |
| Contact handling | Start with a controlled email or task destination; add CRM persistence after the workflow is proven | Proposed |
| Supabase | Defer until persistent inquiry storage or dashboard requirements are confirmed | Proposed |
| Analytics | Add privacy-reviewed analytics after the event contract is approved | Proposed |
| Pricing visibility | Use inquiry-led pricing until package pricing is approved for publication | Proposed |
| Proof points | Publish only approved testimonials, case studies, or process evidence | Proposed |
| Privacy and retention | Define the privacy notice and inquiry retention before production form storage | Proposed |
| Launch ownership | Assign one owner for inquiries, alerts, rollback, and final release approval | Proposed |

## Why These Defaults

These defaults keep the first release focused on Micade's service-led model and reduce irreversible integration work. They preserve a clear visitor journey while allowing the website to expand into resources, education, AI, software, and community later.

## Implementation Release Gate

The Next.js migration can begin after the following are approved or explicitly deferred:

- Primary CTA and launch page list.
- Content briefs and package scope.
- Contact destination and privacy/retention approach.
- Analytics approach and event contract.
- Ownership for inquiries, incidents, rollback, and release approval.
